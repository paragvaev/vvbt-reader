# VVBT Reader

Небольшая статическая читалка для писем, опубликованных приложением ВВБТ. Проект не редактирует документы и не обращается к Dropbox API: он получает только публичный `publication.json` и публичные изображения.

## Локальный запуск

```bash
npm install
npm run dev
```

Откройте адрес, передав публичную Dropbox-ссылку в URL-кодированном виде:

```text
http://localhost:5173/?publication=<ENCODED_PUBLICATION_JSON_URL>
```

Если один JSON содержит несколько писем, можно дополнительно выбрать письмо по slug или ID:

```text
http://localhost:5173/?publication=<URL>&letter=<LETTER_SLUG>
```

Для публикации одного письма из ВВБТ параметр `letter` не требуется.

## Сборка и тесты

```bash
npm test
npm run build
```

Результат находится в `dist/` и подходит для любого статического HTTPS-хостинга: GitHub Pages, Cloudflare Pages, Vercel или собственного сервера.

Ветка `main` автоматически публикуется через GitHub Actions по адресу:

```text
https://paragvaev.github.io/vvbt-reader/
```

## Tilda

Самый простой тест — разместить читалку на статическом хостинге и вставить iframe из `examples/tilda-embed.html` в HTML-блок Tilda. Для каждого письма используется собственная страница Tilda и собственная публичная ссылка `publication.json`.

Iframe использует `100dvh` на настольных браузерах и безопасную высоту `100svh` на мобильных. Это не даёт нижней панели Safari перекрывать интерфейс при открытой адресной строке. Плашка «Made on Tilda» принадлежит родительской странице Tilda и находится вне iframe; высота iframe не удаляет её.

Повторная публикация письма из ВВБТ с тем же slug обновляет Dropbox-файл. Страница Tilda и её настройка при этом не меняются.

Обычные публичные ссылки `www.dropbox.com/scl/fi/...` автоматически переводятся читалкой на CORS-совместимый домен `dl.dropboxusercontent.com`; параметр `rlkey` сохраняется.

## Безопасность

- В проекте нет Dropbox OAuth-токенов и секретов Tilda.
- Данные публикации считаются публичными.
- Контент вставляется через DOM `textContent`, а не как доверенный HTML.
- Поддерживаются только публичные HTTP(S)-адреса публикаций.

## Персональная серия писем (Cloudflare prototype)

Читалка также поддерживает персональный режим для асинхронной серии из восьми писем. Статические файлы и API разворачиваются одним Cloudflare Pages-проектом, а состояние подписчиков хранится в D1.

```text
SendPulse Automation 360
  → /api/sendpulse/subscribe
  → D1: дата начала и хеш персонального токена
  → https://wwy.vlsv.gay/?t={{reader_token}}&letter=pismo-1
  → /api/session
  → только уже доступные письма
```

Email и исходный персональный токен в D1 не хранятся: сохраняются только SHA-256-хеши. После первого открытия читалка убирает токен из видимого URL и хранит его локально на устройстве. Публичный режим `?publication=…` остаётся совместимым с GitHub Pages.

### Cloudflare

```bash
npm run cloudflare:db:remote
npm run cloudflare:deploy
```

Конфигурация находится в `wrangler.jsonc`, схема — в `migrations/`. Восемь записей `letters` содержат номер, slug, название, задержку в днях и Dropbox `publication_url`. Перед запуском серии заполните URL каждого опубликованного письма через D1 Console или `wrangler d1 execute`.

Рабочий вариант обновляет эти записи прямо из настольного ВВБТ. После загрузки отдельного письма в Dropbox приложение вызывает защищённый `POST /api/admin/publications` и передаёт номер, slug, название, задержку и публичную HTTPS-ссылку `publication.json`. Endpoint обновляет соответствующую строку D1, поэтому ручное редактирование таблицы не требуется. `GET /api/admin/publications` используется для проверки соединения.

Защищённый `GET /api/admin/publication-links` возвращает уже созданные ссылки опубликованных писем для настольного ВВБТ. Он только читает D1: просмотр ссылок не переопубликовывает письма и не создаёт новые токены. В приложении ссылки доступны через **Опубликовать… → Постоянные ссылки…**; для каждого письма можно скопировать ссылку только на него или на всю серию с него.

При первой регистрации Cloudflare создаёт одну длинную случайную общую ссылку серии. Для каждого slug также создаётся отдельная стабильная ссылка только этого письма. Индивидуальный токен возвращает через API ровно одно письмо, поэтому подмена параметра `letter` не открывает остальные публикации и переключатель писем не показывается. Общая ссылка серии открывает выбранное письмо сразу и показывает все письма с зарегистрированным `publication_url`. Расписание подписчика к обоим видам статического доступа не применяется. Ключи хранятся централизованно в D1 и не зависят от конкретного Mac или `.vvbt`-файла; повторная публикация с тем же slug сохраняет прежние ссылки.

Общая ссылка является bearer-доступом: прочитать опубликованные письма сможет любой человек, которому её передали. Не публикуйте её открыто, если это не является намеренным. Персональные SendPulse-ссылки и их календарь работают независимо.

Для этого задайте одинаковый случайный секрет в двух местах:

- Cloudflare Pages secret `PUBLICATION_ADMIN_KEY` проекта `vvbt-reader`;
- ВВБТ → **Настройки → Читалка**; приложение хранит значение в macOS Keychain.

Это отдельный ключ одного служебного endpoint, а не Cloudflare API token. Его нельзя помещать в репозиторий, `.dev.vars`, `.vvbt` или `publication.json`.

Поддомен `wwy.vlsv.gay` подключается как Custom domain проекта `vvbt-reader`. Поскольку DNS домена обслуживает Tilda, в Tilda DNS нужна запись:

```text
Тип: CNAME
Имя: wwy
Значение: vvbt-reader.pages.dev
```

Сначала поддомен необходимо добавить в Cloudflare Pages → `vvbt-reader` → Custom domains, и только затем создавать CNAME.

### SendPulse

Production-секреты задаются только через Cloudflare Pages secrets:

- `SENDPULSE_WEBHOOK_KEY` — случайный ключ входящего webhook;
- `SENDPULSE_CLIENT_ID` и `SENDPULSE_CLIENT_SECRET` — API-реквизиты SendPulse;
- `SENDPULSE_ADDRESS_BOOK_ID` — ID адресной книги.

Дополнительные разрешённые книги перечисляются в `SENDPULSE_ADDRESS_BOOK_IDS`. Worker пытается записать `reader_token` во все настроенные книги, где API принимает обновление контакта. Сейчас разрешены рабочая `WWY` (`992404`) и тестовая `WWY TEST` (`1145458`); произвольный ID из webhook не принимается.

Общий запуск WWY задан переменной `CAMPAIGN_LAUNCH_AT` в `wrangler.jsonc`: `2026-08-10T15:00:00.000Z`, то есть 10 августа 2026 года в 18:00 по Москве. Для подписавшихся раньше этой даты `started_at` равен моменту общего запуска; для подписавшихся позже — фактическому моменту регистрации.

В Automation 360 добавляется webhook после входа подписчика в цепочку:

```text
https://wwy.vlsv.gay/api/sendpulse/subscribe?key=<WEBHOOK_KEY>&email={{email}}
```

Endpoint создаёт или обновляет подписчика, вычисляет дату старта как более позднюю из момента регистрации и общего запуска, а затем записывает персональный токен в строковую переменную контакта `reader_token`. В ссылках писем используется одна и та же переменная; номер/slug письма не является разрешением доступа — сервер всё равно проверяет дату.

Automation 360 ожидает от Action: Send webhook JSON-массив с полями `status`, `message` и `code`. Endpoint отвечает именно в этом формате и умеет брать email как из `?email={{email}}`, так и из стандартного JSON-массива события SendPulse. Обычный `{ok:true}` не подходит: SendPulse считает его некорректным ответом и может ограничить последующие webhook-запросы.

### Ограничения прототипа

- Настройка рабочего Automation 360 требует API-реквизиты, ID адресной книги и тестовый контакт.
- Dropbox-файлы остаются публичными capability-ссылками. Читалка не раскрывает URL будущих писем, однако уже известный прямой Dropbox URL нельзя отозвать через этот сервер.
- Состояние последнего прочитанного письма хранится в D1, но позиция прокрутки пока остаётся локальной.
- Wrangler используется только при разработке и развёртывании. Найденные `npm audit` advisories относятся к его локальной цепочке Miniflare/Undici и не входят в браузерную production-сборку.
